# Reference reconstruction and visual review

LLcad separates native geometry validation from resemblance to a reference. `cad_get_model.reference_validation` and the viewer's **Reference review** panel expose the same revision-bound result. There is no claim of a physically exact replica from a photograph.

## Workflow

For named products, the reconstruction agent must first inspect the available user attachment and research the exact variant using its web search/fetch tools. Save manufacturer image URLs and original images; check variant and operating state. LLcad's reference MCP tools accept supplied images and do **not** implement an internet search engine. The viewer's reconstruction agent has WebSearch/WebFetch available and receives these instructions in its generated tool guide; the global reconstruction skill contains the same workflow. A missing user attachment must be disclosed, not silently replaced with an assumed defect.

Upload original PNG/JPEG/WebP images through authenticated `POST /api/uploads`. Create a model, then call `cad_reference_setup` with its current `base_revision`, reference artifact IDs and `expected_contract_hash:null` (or the previous contract hash when updating). Optionally supply source-backed dimensions, millimetre tolerances, explicit contact pairs, camera registrations and model selection. Source artifacts retain their hashes.

Build a visible coarse MVP first and inspect it with `cad_reference_check` phase `inspect`: 1–3 chosen local viewer captures, no paid AI, no mandatory inventory and no repeated full native contact/dimension checks. Refine independent features through `cad_feature_batch`; see [MVP and parallel feature workflow](mvp-feature-workflow.md). Use optional paid `phase:inventory` when source complexity needs help. Inventory completion creates a **new contract hash**; read its pages and reconcile observations with sources before final comparison.

Model through normal plan/apply/validate/commit tools, grouping compatible local corrections. Reserve `cad_reference_check` with `phase:compare` for a complete final review of an exact candidate or committed revision. It captures the actual built viewer with its effective material settings from six viewpoints and any supplied reference cameras. It checks native B-Rep validity, declared dimensions and contact gaps; registered images additionally receive silhouette IoU and contour F1 checks. Unregistered photographs do not get misleading pixel scores.

### Acceptance policy

Every contract records how a final `compare` review passes (`acceptance`, frozen with the contract hash):

- **`gates_judge` (default for new contracts).** The deterministic floor decides: `cad_gates` must report `floor_passed: true` on the reviewed revision, and every native check of the run (B-Rep validity, declared dimensions and contacts, registered silhouette IoU and edge F1) must pass. On top, **one** judge (default `claude -p --model claude-opus-5-5`, effort `xhigh`) reviews registered crop triples (source | render | silhouette residual) with set-of-mark part numbers and answers 2–5 binary questions per ledger item (`requirements[].questions`, else category templates); with a previous judged revision it also compares before/after pairwise with the image order swapped, counted only when both orders agree. The judge is advisory: a "yes" whose region disagrees with the registered projection of the item's `feature_ids` is downgraded to uncertain, and a "no" is only a candidate defect. A candidate defect is **confirmed** by a deterministic probe (silhouette residual > 10 % or CIEDE2000 source vs albedo render > 10 inside the judged region, a matching `cad_gates` residual, or a failed native check of that view) and then blocks (`needs_correction`), or it is **refuted** (region elsewhere), or it stays **unconfirmed**. An unconfirmed critical finding (required item) keeps the review at `insufficient_evidence` until the item is fixed or explicitly accepted in the contract's `accepted_assumptions` (requirement id + note); everything else goes to the run's assumptions list for the user. Items whose references have no camera are covered by the gates only. Without `cad_gates` in the build, or when a judge call fails after its retry, the review cannot pass.
- **`two_vlm` (selectable).** The earlier rule: independent OpenRouter model findings (`models`) are joined by frozen requirement ID; at least two distinct models must each supply exactly one confident match for every required detail. Missing, duplicate, low-confidence or occluded evidence cannot pass. Any additional visible defect or failed native check blocks a pass. Model confidence is a judgment, not calibrated probability. Contracts frozen before the policy existed carry no `acceptance` field and keep this rule.

The judge route is selectable per contract (`judge.provider`: `claude_cli` or `openrouter` with an OpenRouter model id; `judge.effort`, `judge.max_parallel` 1–3, `judge.pairwise`, `judge.max_cost_usd` default $5 of reported cost per run). Judge and vision calls run in parallel (bounded) and each call is retried once on `VISION_INCOMPLETE` or `VISION_INVALID_RESULT`; parallel calls share one cost ledger with in-flight reservations. Identical judge requests (same prompt, image bytes and judge) and captures of unchanged geometry, appearance, renderer and cameras are reused across runs, so changing only the contract (for example accepting an assumption) costs no new capture or judge call. Captures of camera references use the camera as given: absolute cameras (`mode: "absolute"`, see below) are never rescaled to the model's bounds; the judge route adds an `ids` channel (part numbers, projections) and an `albedo` channel (flat declared colours for colour probes). Decals and the default configuration are captured as the viewer shows them. Use the correction suggestions for normal CAD patches and compare again. A fixed correction count is not grounds to leave a directly actionable marking error. Avoid repeated paid calls on unchanged evidence; identify the next concrete edit or the specific missing evidence/user budget that prevents progress. The tool never runs generated CAD code or secretly mutates the model.

For a disputed marking, the agent must add separate required checks for position relative to body landmarks, size, orientation, outline/text and rendered colour. Inspect the marking directly at useful detail resolution in both the source and actual viewer before repeating a whole-product review. A broad "orange logo on the lower handle" finding, a generic brand SVG or a material hex code cannot establish those details. Compare corresponding views and account for lighting/tone mapping; uncalibrated photo colour is an appearance target, not a physical pigment measurement. These are agent workflow instructions, not a new deterministic colour or position certification. Feature counts and native check counts do not demonstrate visual similarity.

The viewer can upload a new reference set, run inventory/comparison, show status, paginate findings and open source/render/difference images. New reference uploads reset the visible inventory. They preserve configured native constraints and model choices; full contract editing is available through MCP.

## Export and binding

A report binds the reference contract, IR, native facts, effective part materials, viewer bundle and exact captured revision. Candidate proof may be reused for its identical committed geometry and appearance. Changes make the result stale. A native commit can retain an unfinished visual draft; it is never renamed a reference-accurate result.

Configured reference models require `matches_declared_visible_checks` for default `cad_export`, under the contract's acceptance rule: for `gates_judge` the exact revision's run must also carry `floor_passed: true` and no open critical judge finding; for `two_vlm` the two-model agreement. Explicit `reference_policy:draft` exports carry their draft classification. Models without a reference contract retain their normal export workflow and are labelled `not_configured`. Exports include `reference-review.json` and manifest status alongside native validation. The gate is checked both before queuing and when packaging the completed export.

## Runtime configuration

- `LLCAD_OPENROUTER_KEY_FILE`: private file containing an OpenRouter key, or `LLCAD_OPENROUTER_API_KEY` supplied by the deployment environment.
- `LLCAD_CHROMIUM_PATH`: optional Chromium executable (defaults to `/usr/bin/chromium` if available).
- `LLCAD_IMAGE_PYTHON`: optional Python executable with Pillow, NumPy and SciPy (defaults to `.venv/bin/python`).
- `LLCAD_JUDGE_CLI`: optional path of the `claude` CLI for the judge (else `MATHFORGE_CLAUDE_CLI`, `~/.local/bin/claude`, `/usr/local/bin/claude`). The judge runs without tools, MCP servers or settings sources (no user hooks), with `--json-schema` structured output and `--max-budget-usd` set to the remaining judge budget.
- `LLCAD_VISION_PARALLEL`: parallel OpenRouter calls of inventory and `two_vlm` comparisons (1–3, default 2).

### Absolute cameras

`references[].camera` accepts the old bounding-box-relative camera or an absolute one: `{mode:"absolute", projection:"perspective"|"orthographic", position_mm, target_mm, up, fov_deg (perspective, vertical) | mm_per_px (orthographic), width_px, height_px, principal_px?}`. The same contract is used by the viewer's `captureReference`, the VTK renderer and `cad_fit_parameters`. The Reference Pack (`tools/reference-pack`) derives orthographic cameras from turntable frames scaled to a datasheet height.

### Fitting variables to registered views

`cad_fit_parameters` fits declared model variables (`set_variable`, `{var}` expressions; up to 12, with bounds) to references that have registered absolute cameras. Tier 1 is a 2D stand-in built from real candidate renders (silhouette signed-distance fields at the current values and one step per variable, linear in between) searched with bounded Powell over (1 − IoU), mean edge distance in mm and optional landmark residuals; tier 3 builds the optimum as a real candidate and measures it, with one re-linearisation when the two disagree or the optimum lies far from the samples. The result is a proposal of `set_variable` operations with before/stand-in/confirmed metrics. It never commits and discards every candidate it built; apply, validate and commit the proposal normally.

Dependencies: pinned Playwright, Chromium, and the existing native CAD Python environment. Root Chromium uses `--no-sandbox` inside the service sandbox. Capture contexts route only their bound model's read APIs and preview artifacts; unrelated browser network requests are denied. Selected images are sent by the server to OpenRouter. No API key enters the browser or report.

Default OpenRouter models (inventory and the `two_vlm` rule): `qwen/qwen3-vl-32b-instruct` and `google/gemini-2.5-flash`. The current OpenRouter catalog is consulted for image/structured-output capability and token prices. `maximum_cost_usd` defaults to $0.50 per run; conservative token reservations precede calls and actual provider usage is recorded. It is not an account-wide billing cap. Provider failure, unknown cost, invalid/incomplete output or a 10-minute timeout produces no approval. One review runs at a time; a `gates_judge` comparison has a 20-minute deadline, other phases 10 minutes. Idempotency keys prevent duplicate paid runs; completed unchanged comparisons are cached. Interrupted runs are failed after restart.

## Scope and limitations

`matches_declared_visible_checks` means only that the declared visible requirements passed the available checks. Hidden surfaces, physical texture, unknown dimensions, optical performance and manufacture require additional evidence. Specular/transparent surfaces and uncalibrated viewpoints can remain uncertain. A source-backed contact graph must declare relevant mating parts; unconstrained disconnected objects rely on visual review and are not globally certified. Registered contour metrics include disconnected foreground components and have a two-pixel edge tolerance. They do not check material or text fidelity by themselves.

Regression tests under `tests/reference-review/` include negative evidence, stale proof, authorization, floating image components, real native geometry, the shipped viewer, structured tool contracts and export gating. Mock-provider integration tests check orchestration, not recognition accuracy; live trials must be reported separately.

Inventory is extracted in bounded image batches, then reconciled against the original photos. Comparison independently checks whether each inventory assertion is actually supported by its source. Contradicted or uncertain source assertions become unresolved evidence, not instructions to distort the CAD model. `cad_reference_report.checked_summary` describes the requested historical run; `reference` describes the current revision. New runs retain their full input contract, and expose their complete report artifact even after later revisions make them stale.

The original-material viewer uses transmission and refraction for glass. GLB exports carry the effective PBR colours, roughness, metalness, transmission, IOR and glass thickness alongside `appearance.json`; the native checked binary geometry is preserved byte for byte. Appearance depends on the receiving renderer and lighting. STEP has native geometry and sidecars, not a promise of identical rendered pixels.

Long correction sessions can remove obsolete construction with `remove_feature` and the expected full feature hash from `cad_inspect.feature_hash`. Graph references, outputs, constraints and downstream protection still apply. Removal changes only a new revision; historical revisions remain intact. This avoids growing past the existing data budget without weakening that budget.

Provider output is constrained to the exact requirement and image IDs supplied in each batch, preventing invented cross-references from being accepted. Validated partial findings are retained if a later call fails. A retry can reuse complete native checks only from identical IR, native geometry/build facts and native dimension/contact rules; a failure or unknown measurement stays a failure or unknown. Reusable captures and complete reviews retain their source provenance; missing visual evidence still requires a new provider result. Each call is retried at most once, and only for an incomplete or invalid answer; budget, provider and usage errors are never retried.

A retry also reuses exact stored viewer PNGs and complete model reviews only from the same full frozen fingerprint (including appearance and renderer), recording source run and request IDs. Partial or invalid model responses never substitute for a complete review. New usage lists only newly billed requests; prior costs remain on the source runs. This behavior is covered by a provider-interruption integration test. Models advertising supported reasoning budgets receive a bounded reasoning setting and enough space for their structured answer; costs are still reserved before the request. See [OpenRouter reasoning budgets](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens) for the provider behavior behind these settings.

The original-material viewer now provides environment reflections to metals and plastics as well as glass, with filmic tone mapping to retain bright surface detail. Diagnostic display channels keep their previous tone mapping. Appearance-only changes invalidate the visual result; complete native measurements can still be reused when the exact native inputs and contact/dimension rules match.

Validated complete requirement batches also survive a provider interruption. Retries reuse only complete batches for the same captured pixels and contract, retain the original run IDs, and request missing batches again. Incomplete batches are replaced, so partial retries cannot create duplicate positive findings. Requests have a bounded three-minute provider timeout within the overall ten-minute run deadline; interrupted response transfers are reported as provider errors. The integration fixture deliberately fails after the first of multiple requirement batches and verifies correct, unbilled reuse of that batch.
